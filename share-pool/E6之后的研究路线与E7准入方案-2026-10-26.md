# E6 之后的研究路线与 E7 准入方案

> 后续研究决定（2026-10-26）：按用户明确意见，当前先收敛问题发现、验证和边界，不推进 E7。下文保留为候选规划；其中“启动 E7-0”“下一个实现步骤”等建议暂不执行。已做实验与当前状态以 [E1–E6 与九项 Baseline 总报告](截至2026-10-26实验总报告-E1至E6与九项Baseline.md) 为准。

日期：2026-10-26。状态：完成现有证据与源码可行性审查；E7 新实验尚未运行。

## 1. 当前决定

**E6 保持限定范围结项。下一步优先收敛论文的测量贡献，同时启动 E7-0 的证据可得性审计；暂不预设新防御，也不直接扩张大矩阵。**

推荐的研究主线是：环境事实经低信任 Producer 进入规划和最终授权时，什么来源、目标绑定与时间覆盖条件足以支持安全授权？同源最新消息为什么仍会失败？强简单防御在什么权限假设下已经足够？

这与 [Proposal-3](Proposal-3.md) 默认选择 C2（信任边界测量）、有条件选择 C3（新设计）的路线一致。E7 不是 E6 的补验收，也不是论文成立的自动前提。

## 2. 已有证据能支持什么

| 论文主张 | 当前主要证据 | 可以表述的结论 | 必须保留的限制 |
|---|---|---|---|
| 自洽的错误事实仍会使确定性安全门误授权 | E5-A；E6 开发／压力矩阵 | 指定同源谓词的一致性检查不能认证真值 | 不等于全部 metadata 自洽，也不等于所有一致性防御失效 |
| 同源新鲜度不能修复持续污染 | E6 Shared 与 Same-Source Fresh，开发集各违规 8/8 | 对同一受污染 Producer 再查一次仍可能错误授权 | Same-Source 在线复核未新增；结论来自归档计划轨道 |
| 受保护证据可阻断当前测试的错误授权 | E6 在线 Shared 违规 4/4、Independent Fresh 0/4；正常任务均 4/4 | 自建管线内，两类合同下来源隔离有效 | 同一 Unity 根源的受保护路径；不是独立物理传感器 |
| 属性污染进入在线计划；关系污染进入最终授权 | 在线逐步 trace | 属性假 OFF 到达 Planner；关系旧事实到达运行时 Monitor | 关系首次规划时事实真实；不能说关系污染已诱导 Planner 偏离 |
| 简单关键动作核验具有竞争力 | E6 Critical-only Fresh 成本补充 | 开发攻击／正常各 8 次查询，Hybrid 各 11 次；当前安全与合法完成结果相同 | 不支持 Hybrid 普遍更优；后补批次的延迟不能解释成因果加速 |
| 正确旧证据也可能失效 | E5-C；E2-B5/B7 | 来源可信与时间有效是不同条件 | 用户态二次检查不等于原子执行；不外推自然并发安全 |
| 阻断和任务恢复不同 | E6 在线攻击防御组任务成功 0/4；E5 已有独立恢复批次 | E6 测到授权阻断，没有测到攻击后恢复 | E5 恢复结果不能直接拼入 E6 在线分母 |

优先依据：[E6 正式验收](../E6_ACCEPTANCE_20261025.md)、[E6 完整结果](E6-结项报告-2026-10-25.md)、[E5 验收](../E5_ACCEPTANCE_20261025.md)、[E2 脚本索引](../e2_validation/SCRIPTS.md)。历史方案中“尚未开展”的阶段描述不代表当前状态。

E6 主轨道有 364 个执行回合，分别统计；不能据此声称 364 个独立样本。两个在线新场景不足以支持普遍泛化或精确总体成功率。

## 3. 先做的论文整合

1. **主表 A：权限与传播。** 分别列 Producer 权限、消费端、Planner 是否实际见到假事实、Monitor 是否见到假事实、原生执行回执。把评估器制造的关系变化与攻击者权限分开。
2. **主表 B：强防御比较。** 以 Shared、Same-Source Fresh、Critical-only Fresh 为核心；Independent Fresh、Receipt、Fail-Closed、Hybrid 保留完整对照。所有方法写清额外证据权利。
3. **主表 C：安全、效用与成本。** 分轨报告危险候选分母、违规执行、正常任务完成、合法 DEFER、查询次数和延迟。零危险候选时 UAR 为 N/A。
4. **边界图。** 画出低信任 Producer、可信接收端、Planner、最终 Monitor、受保护查询和 Unity；标明关系路径在规划之后发生状态变化。

这四项可以从已有结果整理，不需要新 API 调用。现有证据支持有限范围的评估贡献；是否足够投稿仍取决于整篇论文的定位、外部有效性及相关工作比较。

## 4. 为什么 E7 应先研究证据可得性

候选名称：**E7 — Evidence Availability and Safety–Utility under Restricted Observation**（受限观测下的证据可得性与安全—效用评估）。

研究问题：当最终 Monitor 没有可直接读取合同真值的受保护 metadata 接口，只能使用有明确权限的 RGB、动作回执或主动观测时，哪些合同仍可判定？简单关键动作核验还需要多少观测、等待或 DEFER？

这是待检验问题，不能预设“去掉真值接口后新方法一定更好”。如果部署确实提供受保护状态接口，Critical-only Fresh 必须继续作为可用强基线；只有研究目标本身不提供该接口时，才将它作为明确标注的上界。

E2 已有视觉、错误炉头、目标绑定、旧图重放和 TOCTOU；E5 已有任务恢复。单独重做这些现象没有建立新的贡献。E7 的增量应是**同一证据权限下，观测是否足以支持合同、核验成本及安全任务完成的系统比较**。

## 5. E7-0 源码审查：已确认的复用边界

本节是静态代码发现，不是新运行结果。对应文件哈希见 [源码审查清单](../results/E7/00_feasibility/source_audit_20261026_01.json)。

| 组件 | 已核对的事实 | 对 E7 的含义 |
|---|---|---|
| [E6 Producer 接收端](../e6_validation/producer_boundary.py) | 真 JSON 管道；接收端校验允许字段，并附加来源记录 | 可参考边界设计；E7 新增视觉通道须单独审查权限，不能只复用 source_id 字符串 |
| [E6 关键动作 Fresh](../e6_validation/runtime_v4.py) | 仅关键候选路由到独立查询；无初始可信缓存 | 必须保留为强简单基线／上界，不能只比较每步重查来突出成本优势 |
| [E2 相机探查](../e2_validation/stove_camera_view_probe.py) | 使用私有位置、visible 和对象类型评分选择相机；使用 TeleportFull | 旧图片不能直接作为无真值主动感知的公平证据；转位也不是零成本真实导航 |
| [E2 ROI 对照](../e2_validation/b2d_roi_perception_pair.py) | ROI 人工参考两张图选择 | 可作历史诊断；正式评估需冻结选择规则，禁止按测试答案选裁剪 |
| [E2 目标视觉识别](../e2_validation/b3c_target_specific_vlm.py) | 固定相机人工标定 front-right；无自动可信旋钮到图像映射；无运行时授权 | 不能直接声称已有可部署目标绑定防御或 E7 闭环结果 |
| [E2 执行前复核](../e2_validation/b7e_preexecution_revalidation.py) | 已有原生执行前核验试验 | E7 不以“再查一次可阻断”作为新贡献 |

特别注意两类合同的语义：RGB 中看似放在炉头上，不必等于 E6 的 `parentReceptacles` 成员关系；看见旋钮也未必能可靠判定 `isToggled`。需要先核验可观测性。无法辨别时应记 UNKNOWN，不能凭视觉输出补出隐藏语义。

## 6. E7-1 最小可行性试验（待实现／待运行）

先采集证据，不调用在线 Planner，也不运行大规模攻击矩阵。

建议上限为 **24 个条件化观测记录**：2 类合同 × 2 个已用开发场景 × 3 条件 × 2 种预先固定视角条件。条件为 clean-safe、clean-unsafe、unsafe＋Producer 假安全事实；视角条件为预设清晰视角与预设受限视角。它们是配对观测，不是 24 个独立任务或执行回合。

只用已用开发场景设计规则。E6 FloorPlan9/10 已被观察过，后续可以复用测试机制，但不能重新称为独立未知 E7 heldout。真正泛化集应另选、在开发规则冻结后保留。

采集前必须完成：

- 定义目标身份如何交给核验器；同一方法比较中，目标提示、标定或 ROI 的权限一致。
- 相机规则在看本轮答案前冻结。若使用人工标定，所有对照同等获得并单列成本；若使用 GT 辅助相机选择，明确标作辅助上界。
- RGB 路径绕过受攻击 Producer；攻击者仍只改冻结字段，不能修改 RGB、合同、评估器或可信回执。
- Monitor 输入与 evaluator GT 分文件、分通道；metadata 只给 evaluator 时，不得经 prompt、裁剪、置信度或目标框泄漏。
- 完整记录时间、图像哈希、对象绑定来源、回执覆盖范围、所有查询、观测移动和失败。静态阶段不声称并发时序保证。

先回答“在这些权限下能看见什么”。固定核验器或人工盲读可作可辨性诊断，但人工读出不是自动化 Guard 成功率，单次 VLM 判断也不是总体准确率。若引入 VLM，应先验证真实支持图像的模型端点，再冻结版本和调用预算。

## 7. 进入运行时比较的条件

可观测性可行后，再冻结以下同权限对照：

| 对照 | 允许信息 | 目的 |
|---|---|---|
| Same-Source Fresh | 原 Producer 最新输出 | 传播参考；不赋予不存在的可信性 |
| Critical-only Observation | 关键动作前按需获取目标绑定的新鲜 RGB／可用回执，不足则 DEFER | 强简单非全知基线 |
| Receipt + Observation | 相同回执与 RGB；回执覆盖不足时观测 | 检查复用是否实际节省成本；不是默认新方法 |
| Fail-Closed | 相同公开信息，关键证据不足则停止 | 显示低攻击率对应的任务损失 |
| Critical-only Metadata Fresh | E6 受保护 Unity 真值接口 | 单列上界；若实际可得，则必须列为部署候选 |

若允许主动观察或安全恢复，各方法具有相同动作集和预算；不能只给候选方法重规划机会。输入不支持、解析失败、超时、动作失败分别报告，不自动计入防御成功。

主要指标为原生违规执行与正常安全任务完成，并列合法 DEFER、危险候选 UAR、证据可判定覆盖率、观测／模型调用次数及完整决策时延。攻击后恢复单列，不能用拒绝代替恢复。小规模阶段展示逐配置结果，不用配对重复构造窄置信区间。

## 8. 停止或扩张标准

| 实际观察 | 下一步 |
|---|---|
| 合同语义在允许证据中无法区分 | 记录不可判定边界，维持 DEFER；不进入该合同的“识别成功率”排名 |
| RGB 只能支持另一种几何语义 | 如有研究价值，另立版本合同并重新验证；不得改写 E6 历史合同或混合分母 |
| 简单按需观测已经低成本解决 | 接受简单防御有效的结果，完善评估论文；不强行开发新 Monitor |
| 存在重复可见的额外观测／合法任务损失 | 先解释代价来源，再在开发集预注册可接受安全、效用及成本标准，决定是否提出小方法 |
| 候选方法在相同证据、动作和预算下确有收益 | 冻结方法与指标，再进入新场景测试；不从测试结果反调规则 |
| 只有 Simulator 真值查询能解决 | 写清其权限前提与其他通道的不可观测边界；不宣称来源隔离等于物理真值认证 |

E7 的成功标准是把证据条件与授权边界说明白，不是必须让攻击成功，也不是必须证明复杂方法优于 Fresh。

## 9. 与相关工作的关系

2026-10-26 重新查阅以下原始论文页面；这是定向核对，不是完整新颖性检索：

- [ESTI，v3](https://arxiv.org/abs/2608.16806v3)：已经研究环境状态文本经属性、空间关系等影响规划与执行。因此“污染环境文本导致执行偏离”不能单独作为本研究的新贡献。
- [RoboGuard，v2](https://arxiv.org/abs/2503.07885v2)：已经有安全规则情境化与时序逻辑控制合成；不能把独立安全门这一结构本身当作新颖点。
- [SafeGate](https://arxiv.org/abs/2604.05427v1)：已经包括执行前确定性门、任务安全合同和运行中约束检查。因此 E7 需要展示证据权限、可观测性与实际安全—效用成本的具体增量。

据此作出的研究判断是：当前更稳妥的主线为限定系统中的证据信任边界测量。E7 是否支持额外设计贡献，需要公平比较结果，不能仅凭命名或架构图确定。

## 10. 完成状态与下一个执行步骤

本轮已完成：现有研究结论收敛、主张—证据映射、六个相关源码组件审查、E7 小试验设计与停止标准。没有修改冻结 E6 源码、协议或结果，没有启动 Unity 或模型请求，没有新增 E7 运行成功率。
