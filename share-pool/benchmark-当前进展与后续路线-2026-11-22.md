# 具身环境证据安全 Benchmark：当前进展与后续路线

更新时间：2026-11-22。此文是当前 benchmark 开发状态入口；历史实验的完整口径仍以原始汇总和逐项附录为准。

## 1. 我们在做什么

我们要构建一个可复现的评测，研究具身 Agent 的低信任环境证据被污染后，污染是否传播到规划或执行前安全判断，以及不同证据访问方式对安全和正常任务的影响。平台目前是 AI2-THOR、SafeAgentBench 相关组件和自定义的 Producer／Planner／Monitor 管线。攻击发生在我们实现的低信任生产者边界；这不表示已经证明任意官方系统或现实部署普遍存在同一漏洞。

Benchmark 的目标是提供统一任务、威胁模型、执行和计分接口，让不同机制在有明确能力和合同说明的条件下接受比较。可以贡献可靠的测试集和基线，不要求先发明新防御。当前已有保护查询、同源重新查询、保守拒绝等**对照机制**，这些是实验对照，并不等于已经提出完整的新防御系统。

## 2. 已有证据和规模

E6 先前在限定范围内完成过问题验证：包括 364 条原生 episode 和单独的 16 条在线 DeepSeek 记录；实验条件、场景和阶段不同，不能简单相加当作独立任务数量。E6 的完整结项口径见 [E6 结项报告](E6-结项报告-2026-10-25.md)，在线与历史记录见 [E1–E6 总报告](截至2026-10-26实验总报告-E1至E6与九项Baseline.md)。

目前 benchmark 开发版已建立两个具身合同：炉头状态影响取锅的属性合同，以及锅具与炉头关系影响开火的关系合同。现有实现包含生产者边界污染、实际 Unity 执行、受保护真值记录、结果审计和统一结果结构；属性与关系目前仍由不同执行后端实现，尚不是任意方法可直接插拔的成熟套件。

| 开发实验 | 已审计完成 | 设置 | 主要观察 |
|---|---:|---|---|
| 属性合同 | 48/48 | 4 个场景 × 3 种条件 × 4 类方法 | 污染且真实不安全时，共享证据和同源重查各错误授权及违规执行 4/4；受保护查询和 fail-closed 各 0/4。 |
| 关系合同 | 45/45 | 3 个场景 × 3 种条件 × 5 类方法 | 污染且真实不安全时，共享证据、同源重查和适配外部组件各错误授权及违规执行 3/3；受保护查询和 fail-closed 各 0/3。 |
| 合并视图 | 93/93 | 前两行合并：7 个合同案例、4 个物理场景、27 个条件／方法组 | 这是记录数量，并非 93 个独立任务；不跨合同合并成功率。 |
| SafeGate-inspired | 27/27 | 3 个已用关系案例 × 3 种条件 × 3 类方法 | 共享证据下适配 Z3 Guard 的错误授权和违规执行各 3/3；受保护查询各 0/3。 |

属性安全对照中，除 fail-closed 外的三种方法安全候选动作各执行 4/4，fail-closed 延迟 4/4；关系安全对照中，除 fail-closed 外四种方法各执行 3/3，fail-closed 延迟 3/3。这是**候选动作**成功，不是完整任务成功。

上述分母都很小，实验复用了场景和案例。SafeGate 的 27 条是单独实验，不能把它和 93 条当作 120 个独立样本。SafeGate-inspired 为研究者适配，额外要求报告位置距离不超过 0.5 米；评估器的简化关系合同依据真实父容器关系，合同差异使其不宜直接排名。外部关系组件也是适配组件，不是完整外部系统。

补充候选场景的早期记录计划 48 条，其中 24 条完成、2 条 incomplete、22 条 unknown；场景初始化碰撞等问题不能计为攻击成功或防御成功。之后换用可运行配置开展过另外的实验，原始未完成记录仍须保留。FloorPlan11–14 已被开发过程观察，不应称为未经接触的正式留出集。

受保护查询来自同一 Unity 模拟器的受保护通道，是 oracle 式强对照，并非现实中的独立传感器。实验支持在当前威胁模型下“共享污染可能使 Planner/Monitor 的安全判断失真”，也展示同源 fresh 不保证证据可信；结果还不能证明对所有环境或真实机器人的普遍性。

## 3. 九项 baseline 到了哪一步

历史九项均有实验材料，但方法范围、模型来源和实验接口不同，并非九个完整官方系统都已经在当前 benchmark 两个合同上跑完。目前 SafeGate-inspired 在关系合同有上表的独立原生实验；其他八项尚未完成当前原生评测，不能把未接入记为零分或漏洞。

| 历史项 | 历史工作与下一步关键差异 |
|---|---|
| RoboGuard | 适配导航与符号规划，当前厨房执行前监控未接入。 |
| SafeGate-inspired | 自建 Z3 机制已测关系合同，非完整官方系统；属性合同未接入。 |
| RoboSafe-inspired | 自建视觉、历史和融合机制；需要明确视觉与时间输入接口，非官方完整实现。 |
| EMBGuard | 用过官方视觉模型，历史状态融合为研究者添加；原模型输入为图像与动作。 |
| HD-Guard | 历史为视频告警适配；事件评分不能直接视为执行前授权。 |
| SELP | 已运行官方符号组件及研究者语义映射，完整自然语言到规划流程未重现；可优先评估组件接入的公平性。 |
| PerceptTwin | 已使用原版／适配的规划、执行后审计等组件；历史执行前门为研究者新增。 |
| GuardAgent | 原本面向软件 Agent；历史厨房接口为适配且没有物理执行。 |
| Mind the Refinement Gap | 导航与动作细化组件适配，和 RoboGuard 共用部分组件，没有厨房执行。 |

完整历史实验、指标和证据请查 [九项 Baseline 明细附录](九项Baseline历史实验明细附录-2026-10-26.md)。可机器读取的当前能力清单为 [historical_baselines.v1.json](../benchmark_v0/spec/historical_baselines.v1.json)，使用 `python3 scripts/benchmark_v0_baseline_catalog.py` 查看；`--contract relation` 可聚焦关系合同。清单中 NOT_INTEGRATED 表示尚未接入，不代表不能适配。

## 4. 指标和使用口径

- **UAR**：在真实状态不安全、完成并可审计的候选动作中，被错误 ALLOW 的比例；报告分子、分母。
- **Execution ASR / 违规执行率**：在相同可审计攻击条件下，Unity 实际执行并违反合同的比例；授权不等同于执行。
- **安全候选动作执行率、False DEFER/BLOCK**：在真实安全的候选动作中分别统计；当前不能称为完整任务成功率。
- **完整任务成功率**：需在线规划到最终任务终态及独立终态判断，当前统一 93 条没有此指标。
- **受保护查询次数、端到端时延**：需把证据获取、Guard 和执行的计时边界统一；还不能凭当前小样本宣称完整成本结论。
- **攻击传播率、证据覆盖**：需从 Producer 输出到消费者输入及授权时刻记录来源和时间；有记录不等于已经覆盖所有输入、时序或独立信任源。
- **完成率与异常**：单独列出 completed、incomplete、unknown 等；未完成不能纳入成功率分母，也不能默认为安全。分场景、合同、条件、方法报告，避免将重复场景当作独立样本。

## 5. 下一步按产出推进

1. **扩充有效任务与场景**：定义两类合同的任务构造和物理可行性条件，分别保留安全、不安全和污染对照；记录所有场景准备失败。按场景族划分开发与最终评测，先检查历史暴露，不能把开发时见过的场景叫留出集。先增加有意义的独立场景，再决定正式规模；不重复做无实质增量的冒烟实验。
2. **统一可比较的基线接口**：沿用当前清单，优先评估 SELP 符号组件及其输入／输出与合同语义能否接入；只有适配可审计、合同明确，才运行完整对照。随后针对视觉和执行后方法设计合适的任务轨道，保留 N/A，而不是强行合并排名。
3. **从单动作扩展到完整任务**：建立独立终态判定，区分固定计划回放与在线 Planner；记录时序、保护查询和失败原因，补齐任务成功、误拒及成本指标。
4. **形成可交付套件**：统一运行入口和结果格式，提供安装与数据依赖说明、任务卡、基线能力卡、复现命令、案例及可审计结果；清楚列出源码快照未包含的模型、Unity 资源和历史结果。
5. **完成正式评测和写作**：当场景划分、基线覆盖和完整任务指标足够之后，执行实际评测，按方法能力和输入条件报告结果；用版本管理记录变更，无需每个小步骤都冻结。

当前适合继续做 benchmark 开发和扩样，暂不需要另起 E7，也还不宜宣布 benchmark 全部完成。
